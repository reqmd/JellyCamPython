# Диагностика сортировки

Эта версия основана на переданном архиве develop (1e3830c9698a31519b7c9b82b41f904c98172585). Алгоритм STREAM, параметры камеры, морфология, модель, координаты клапанов, длительность и формула срока отправки сохранены.

## Установка

Остановите сервер и сохраните резервную копию рабочей директории. Скопируйте обновлённые `logger.py`, `dsp_protocol.py`, `line_camera.py`, `stream_detector.py`, `sorter.py` в `modbus_ethernet`. В `config.json` добавьте секцию `logging` из архива. Если локальная конфигурация совпадает с переданным архивом, можно скопировать файл целиком. Если используется `config.yaml`, настройки нужно внести в него (он имеет приоритет). Не заменяйте локальные `flat.npy`, `dark.npy`, `background.npy`, `valves.json`, модели и другие данные оборудования.

Запустите сервер обычным `./run.sh`. Переключатели читаются при запуске; для изменения перезапустите сервер. Дата сохраняется в имени файла `logs/YYYY-MM-DD_HH-MM-SS.log`, строки в файле и Python-консоли имеют формат `HH:MM:SS.mmm`. Сообщения пишутся отдельным потоком; при переполнении ограниченной очереди теряются строки диагностики, а не данные камеры, число потерь отмечается в логе. При аварийном завершении процесса последние сообщения могут не сохраниться.

```json
"logging": {
  "log_registers": false,
  "log_objects": true,
  "log_summary": true,
  "summary_sec": 10,
  "log_positions": false,
  "log_detector_debug": false
}
```

- `log_registers`: включает подробные чтения/записи DSP, включая частые запросы статуса, фрагменты и время ответов. При false протокол работает без изменений. Ошибочные запросы и ошибки отправки по-прежнему видны.
- `log_objects`: строка каждого классифицированного предмета, включая класс, который пропускаем.
- `log_summary`: промежуточные сводки, `summary_sec` — период. Итог на остановке печатается всегда.
- `log_positions`: координаты и номера клапанов в строке объекта, подробности раскладки на старте.
- `log_detector_debug`: старые подробные DEBUG/ОТСЕЯНО/СЕРИЯ для детектора общих серий. Ошибки и разрывы потока не скрываются.

## Чтение строки

Пример (синтетические времена, не результат измерений Orange Pi):

```
11:22:33.222 #0001 | Кл=0 99.8% | Сбор=3.00 Дет=1.00 Выр=1.00 Оч=0.20 NPU=1.20 Проч=0.60 | Итог=7.00 мс | OK +3.00
```

Все времена в мс, округление только для отображения.

- Сбор: от расчётной метки первой строки crop до метки последней. Не включает длительность экспозиции как отдельное измерение. Это оценка по времени потока, не аппаратная отметка сенсора.
- Дет: от последней строки до начала `extract_objects`. Включает ожидание окончания TRACK/серии, получение порции, очередь детектора и вычисления детектора. Для группы с несколькими компонентами сбор и детекция рассчитываются по каждой вырезке.
- Выр: вся вырезка завершённой группы, включая получение диагностической метки последней строки. Несколько объектов из одной группы имеют общую длительность вырезки.
- Оч: от завершения вырезки до начала классификации; включает передачу crop и ожидание предыдущих объектов.
- NPU: подготовка входа, вызов модели и получение класса/уверенности.
- Проч: разница между непосредственно измеренным итогом и суммой этапов; например, работа после NPU, поиск клапанов, сохранение crop (если его включить). Показывается, если модуль разницы не меньше 0.10 мс.
- Итог: от t_front до проверки срока отправки после определения клапанов. Раньше проверка срока была до расчёта клапанов; теперь она точнее. Формула due = t_front + delay и допустимое опоздание сохранены. Для пограничного решения статус может измениться из-за более поздней, точной проверки срока.
- OK +X: решение готово с запасом X до установленного срока. ПОЗДНО +X: решение готово на X позже срока, но событие запланировано. НЕ ОТПРАВЛЕН: превышен допустимый предел или другой отказ. ПРОХОД: класс не отбиваем. Это статусы планирования, не физическое подтверждение отбивания.
- При отсутствии метки времени вместо неизвестных измерений выводится `—`. Прежний запасной отсчёт срока от очереди сохранён и явно помечен.

## Остановка и сводка

Регистр 1 = 1 при активной сортировке завершает сессию и даёт одну сводку; повтор записи её не дублирует. Другие команды остановки и метка съёмки работают как прежде. Состояние ожидания означает отключение сортировки, не выключение захвата камеры.

Итог содержит среднее/p95/максимум измеренных этапов, классы, решения, ошибки, потери/разрывы камеры и статистику STREAM за сессию. Проценты решений относятся к классифицированным объектам отбиваемых классов. `SPI: успешных кадров` — успешные вызовы отправки, а не число физических объектов (несколько событий могут объединяться). `SPI откл.` — начало вызова отправки минус назначенный срок по каждому отправленному событию; отрицательное значение возможно при объединении. Фактическое механическое открытие клапанов не измеряется. На стоп показаны отменённые события, уже начатые вызовы SPI и не разобранные объекты; измерения снимаются на момент перехода, не ожидая завершения физической работы.

## Проверки без оборудования

Из `modbus_ethernet`:

```bash
python3 -m py_compile logger.py dsp_protocol.py line_camera.py sorter.py stream_detector.py
./run.sh selftest
python3 test_stream_detector.py
python3 test_logging.py
```

Проверены сборка кадров, независимое завершение объектов, разные размеры порций, края/разрывы, метки времени, протокол с отключённым/включённым логом, оба класса, своевременные/поздние/отменённые решения, повторный стоп, новая сессия, имитация успешной и ошибочной SPI-отправки, многопоточная запись лога. Реальная Jelly 4, RKNN и SPI в среде проверки недоступны; итоговую задержку на Orange Pi нужно измерить на машине.
