# Шаг 1: C++ вырезание (Orange Pi 5, Ubuntu 24.04, aarch64)

Сервер пока запускается с `processing.cut_backend: "python"`. C++-вырезание
использует те же порции снимков треков и возвращает те же BGR crop и времена
первой строки. Если диагностика включена, применяется существующий Python путь.

Перед сборкой поместите ранее скачанный заголовок RKNN в эту папку:

```bash
cd ~/JellyCamPython/modbus_ethernet
mv rknn_api.h cpp/rknn_api.h
sudo apt-get install pkg-config libopencv-dev
make -C cpp
```

Файл `rknn_api.h` должен соответствовать используемому RKNN runtime.
`make -C cpp` создаст `cpp/libjelly_rknn.so` и `cpp/libjelly_cut.so`; старый
`libjelly_rknn.so` из корневой папки можно удалить после проверки запуска.

Проверка сравнивает C++ и Python вырезание на одинаковых синтетических
снимках и требует точного совпадения координат, площади и пикселей:

```bash
python3 cpp/test_cut_parity.py
```

Если тест прошёл, укажите в `config.json`:

```json
"processing": {
  "cut_backend": "cpp",
  "cut_workers": 2
}
```

Остальные существующие параметры `processing` сохраняются. Перезапустите
сервер и сравните с `cut_backend: "python"` при одинаковых настройках:
`Выр`, `ИТОГ`, P95/P99, опоздания, число выданных объектов и ошибок вырезки.
При ошибке вызова C++ конкретный снимок будет обработан Python; такой случай
помечается сообщением «резервная Python-вырезка» и не должен засчитываться
как успешная проверка C++ скорости.

В Ubuntu 24.04 пакет `libopencv-dev` может использовать другую версию OpenCV,
чем Python-пакет `cv2`. Результат теста на этой машине поэтому обязателен;
при несовпадении нельзя переключать рабочую сортировку на C++.

## Пакетный экспорт вырезок

После применения второго патча обязательно пересоберите `libjelly_cut.so`:

```bash
make -C cpp libjelly_cut.so
python3 cpp/test_cut_parity.py
```

В новом варианте C++ выдаёт все метаданные и BGR-данные одним вызовом в
выделенный NumPy-буфер. Вырезки являются представлениями этого буфера и
остаются действительными после освобождения нативного результата. Ключи
`ВходCPP`, `ВызовCPP`, `ЭкспCPP`, `ОбъектыCPP`, `МетаCPP`, `ОсвCPP` в строках объектов и
сводке показывают задержку на границе Python/C++. Переключатель
`processing.cut_backend` остаётся прежним.

## C++ STREAM трекер и подготовка NPU

После следующего патча соберите дополнительные библиотеки на Orange Pi:

```bash
cd ~/JellyCamPython/modbus_ethernet
make -C cpp libjelly_tracker.so libjelly_prepare.so
python3 cpp/test_tracker_parity.py
python3 cpp/test_prepare_parity.py
python3 cpp/test_cut_parity.py
```

Тест подготовки требует точного совпадения всех пикселей с Python и установленной
на устройстве версией OpenCV. Если тест не прошёл, оставьте
`sorting.npu_prepare_backend: "python"`; при несовпадении трекера оставьте
`processing.tracker_backend: "python"`. В отличие от вырезания, ошибка
состояния трекера не переводится автоматически на Python в середине потока.

Чтобы проверить совместную работу после всех трёх тестов, добавьте к уже
используемым параметрам:

```json
"processing": {
  "tracker_backend": "cpp",
  "cut_backend": "cpp"
},
"sorting": {
  "npu_backend": "cpp",
  "npu_prepare_backend": "cpp"
}
```

Сохраните все остальные существующие параметры `processing` и `sorting`,
в частности `cut_workers`, `async_cut`, модель, ядра и прогрев. Режимы
`python` доступны по каждому переключателю отдельно. Включение трекера
не меняет исходную маску и время первой строки объекта. Для контроля
сравните P95/P99 `ИТОГ`, `Выр`, `Подг`, частоту опозданий, число объектов,
сводку STREAM, резервные вырезки и ошибки камеры на сопоставимых прогонах.

## Запись настоящих STREAM-масок для проверки трекера

Добавьте к существующей секции `processing`:

```json
"mask_capture_blocks": 30000,
"mask_capture_dir": "mask_captures"
```

На следующем старте сортировки первые 30000 порций маски после порога
запишутся подряд, включая пустые порции. Запись ограничена одной сессией;
если сортировка закончится раньше, сохранятся уже собранные порции. Разрывы
камеры помечаются сбросом состояния. По достижении лимита архив сохраняется
в отдельном потоке в `modbus_ethernet/mask_captures/stream_masks_*.npz`.
Это диагностический запуск: упаковка масок и сохранение архива добавляют
нагрузку, поэтому его времена нельзя использовать как чистый бенчмарк.

После сообщения `STREAM маски сохранены` запустите:

```bash
python3 cpp/replay_stream_masks.py mask_captures/stream_masks_YYYYMMDD_HHMMSS_ffffff.npz
```

Скрипт сравнивает все завершённые треки по порядку, строкам, координатам,
площади, интервалам и признаку невалидности, а также число активных треков
и объединений после каждой строки. При отличии выведет первую порцию и
строку. После проверки верните `mask_capture_blocks` в 0, чтобы исключить
влияние записи на сортировку. В архиве только бинарные маски и настройки
трекера; цветные кадры и вырезки объектов не сохраняются.
